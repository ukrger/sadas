# Проверка, сборка и критерии приёмки

Unity в среде создания пакета не установлен. Эти команды подготовлены для вашей лицензированной Unity 2022.3 LTS с URP 14/Input System/Test Framework. Они ещё не выполнялись в движке; успешный Python-парсинг C# не заменяет компиляцию.

## Через редактор
1. Импортировать Assets, устранить ошибки Console до генерации.
2. Train Summer → Generate And Validate Long Route. Проверка ищет обязательные ссылки, четыре уникальных радиомодуля, уникальные сохраняемые ID, отсутствующие скрипты и импортные ошибки всех трёх своих шейдеров.
3. Window → General → Test Runner → EditMode / PlayMode → Run All. AimingTests проверяет решение положения/направления маркера; BallisticsTests — стены, паузу, атомарность выделения дробин и урон всей дробью.
4. Train Summer → Build Windows Development Player. Требуется Windows Build Support. По умолчанию Builds/Windows/TrainSummer.exe. Путь можно задать переменной TRAIN_SUMMER_BUILD_DIR.
5. При необходимости Train Summer → Bake Station Occlusion (current scene). Bake синхронный, сохраняет текущую сцену. Только после окончательной генерации: повторное создание сцены стирает её baked-данные/ручные правки. Train/pooled vegetation не помечаются статическими occluders.

## Batch mode
В PowerShell задайте путь к своей Unity и **существующему URP-проекту**, в который скопирован Assets:

    $unityExe = 'C:\Program Files\Unity\Hub\Editor\2022.3.62f1\Editor\Unity.exe'
    $unityProject = 'D:\Projects\TrainSummer'
    & $unityExe -batchmode -quit -projectPath $unityProject -executeMethod TrainSummer.Editor.BuildTools.GenerateAndValidate -logFile validate.log
    & $unityExe -batchmode -runTests -projectPath $unityProject -testPlatform EditMode -testResults editmode.xml -logFile editmode.log
    & $unityExe -batchmode -runTests -projectPath $unityProject -testPlatform PlayMode -testResults playmode.xml -logFile playmode.log
    & $unityExe -batchmode -quit -projectPath $unityProject -buildTarget Win64 -executeMethod TrainSummer.Editor.BuildTools.BuildWindows -logFile build.log

Не добавляйте -quit к Test Runner-командам: дождитесь завершения тестов. Для графических/шейдерных проверок оставляйте доступный графический backend. Не запускайте одновременно несколько Unity на одном проекте. Генератор в batch mode пересоздаёт Generated/Prototype_Long.unity без диалога.

## Ручной интеграционный прогон
- Главное меню действительно держит время/звук на паузе; запуск, RU/EN, параметры, выход из настроек и возврат из паузы не оставляют неправильный курсор.
- Идти/прыгать в движущемся вагоне, выйти/войти на каждой станции, открыть рюкзак на ходу, сохранить/загрузить в вагоне и на земле.
- Подобрать 1/2/3/4; проверить независимый боезапас, одиночные выстрелы/автоматический огонь, дробь, зарядку по одному патрону и отмену зарядки. Пули и топор не бьют сквозь стены.
- Удерживать ПКМ: мушка/целик по центру при FOV 58; отпустить → hip pose/FOV 75. Дрожание/разброс меньше, но не нулевые. Проверить разную частоту кадров и соотношения сторон. Подсказки/крестик не закрывают прицел. Прицельные маркеры корректируются в JourneySetup при изменении модели.
- ПКМ + перезарядка, смена оружия, Tab, Esc, смерть, F9: нет застрявшего FOV/скорости/позиции рук. После закрытия меню 1–2 кадра ввода подавлены, чтобы клик GUI не выстрелил.
- На станции нельзя отправиться до получения её модуля. Модуль даётся один раз. При таймере 0 состав ждёт отсутствующего игрока, топливо или ремонт. Ручное отправление до нуля доступно после получения модуля. Отключение автоотправления сохраняется в слоте.
- F5 → изменить модули/таймер/боезапас/лут → F9: точное восстановление. Проверить миграцию стандартных 0.6/0.7/0.8, загрузку .bak и отказ неизвестной сцены без частичного применения.
- Станции возле игрока остаются активны при отъезде поезда. Дальние отключают NavMesh/AI и включаются при возвращении. Собранные предметы и мёртвые враги не появляются снова. При загрузке далеко от предыдущей станции нужная станция включается.
- Небо проверить в 0.0 / 0.25 / 0.5 / 0.75 времени: ночь/рассвет/полдень/закат. Проверить sky material после F9 и выхода из Play. Луна/звёзды не должны появляться днём.
- Frame Debugger: instanced растения, LOD, тени, depth pass и sun shafts; inventory Overlay не получает лес и лучи. Попереключать качество и разрешение теней; не должно быть потерянных/уничтоженных renderer features.
- Смерть → загрузка/новая игра; четыре модуля + конец пути → экран результата. Дойти весь длинный маршрут, проверить достаточность припасов и возможность восстановления после каждого отказа топлива/ремонта.

## Производительность
Цель для среднего ПК назначается после выбора конкретного CPU/GPU/разрешения; гарантии 60/120 FPS нет. Для 60 FPS бюджет кадра 16,67 мс. Раздельно измерять CPU/GPU в Development Build, GC.Alloc, память и переходы через границы участков. 10 созданных чанков и программный счётчик submissions — лишь часть картины: тени, depth, дополнительные камеры и post-processing добавляют проходы.

Зафиксируйте железо, драйвер, Unity/URP версии, разрешение, пресет, средний FPS, 1% low и пики при прогреве/загрузке. Отключение дальних станций не освобождает их ассеты. Солнечные лучи требуют копирования/временных RT; при GPU-ограничении сначала сравните post-processing On/Off. Occlusion не применяется автоматически к явным Graphics.DrawMeshInstanced batches.
