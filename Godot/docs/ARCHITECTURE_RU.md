# Архитектура Godot-переноса

Точка входа — scenes/main.tscn → scripts/game.gd. Автозагрузок/плагинов нет. Это отдельный проект, не папка для копирования в Unity.

| Файл | Ответственность |
|---|---|
| core.gd | Чистые транзакции инвентаря/крафта/боезапаса, ADS interpolation, окно чанков, проверка контрактов |
| game.gd | Сессия, маршрут/таймер/условия отправления/победы, потребности, настройки, save/checksum/backup, освещение |
| world.gd | Генерация вагона/станций/коллизий/NavMesh, 10 чанков, MultiMesh, occluders, детерминированная декорация |
| player.gd | CharacterBody3D, локальная опора поезда, движение на земле, оружие/ADS/зарядка, изолированный SubViewport рюкзака |
| projectiles.gd | Пул 64 баллистических сегментов/трассеров, гравитация и первые столкновения |
| enemy.gd | NavigationAgent3D, видимость/шум/фонарь, атака, здоровье и анимации |
| assets.gd | GLB cache/LOD selection/material reuse/procedural collider helpers |
| hud.gd | Нативные Control-меню, RU/EN, минимальный HUD, настройки и кнопки крафта |

Слой коллизий 1 — мир/интерактивные StaticBody3D; 2 — игрок; 3 (бит 4) — враги; 4 (бит 8) — Area3D выбора предметов рюкзака в отдельном World3D. Игровые пули не пересекают bag areas. Рюкзак не добавляет физические предметы в пространство вагона. Открытие не останавливает поезд.

На палубе перенос считается через сохранённую локальную точку поезда; горизонтальное движение проходит swept collision. В прыжке сохраняется вычисленная скорость опоры и включается обычный move_and_slide. Это проверено на разгоне/кривом участке, прыжке/посадке и после загрузки с большим телепортом. Нужен дальнейший ручной тест по всему интерьеру и на границах ступеней.

Станции остаются авторскими узлами в RAM; процесс/коллизии/NavMesh выключаются с дальним корнем. Пул окружения защищает продольное положение игрока и поезда, но не создаёт бесконечный мир сбоку. Переиспользуются узлы; геометрия/physics shapes перестраиваются на границе 80 м. У трёх видов оружия общий пул пуль, но отдельные магазины/резервы; дробовик проверяет свободные слоты для всей порции перед расходом патрона.

Сохранение сначала проверяет числа, владение оружием, ёмкости, профиль маршрута, ожидаемые ID и пройденные модули, затем применяет сцену. Запись идёт в .tmp, основной файл становится .bak, временный — основным. Checksum обнаруживает повреждение, не является защитой от редактирования владельцем. Конкурентная запись/несколько процессов в один профиль не поддерживаются. Unity JSON не мигрируется.

В native headless checks загружается настоящая главная сцена, создаётся физика/NavMesh и выполняются её production методы. Это не тесты, повторяющие реализацию на Python. Графическая проверка отдельно выполнялась через Vulkan Forward+ / llvmpipe. Репрезентативные FPS/1% low на дискретной GPU, Windows EXE и полное прохождение длинного маршрута остаются открытыми воротами приёмки.
