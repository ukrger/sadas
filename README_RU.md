# Летний маршрут — технический прототип 0.4

Исходники для **Unity 2022.3 LTS / URP 14**. Это пакет для редактора, не готовый EXE.

## Установка и обновление
1. Создайте проект **3D (URP)** в Unity 2022.3 LTS.
2. Установите **Input System**. Player → Active Input Handling → Input System Package (New) либо Both; перезапустите редактор по запросу.
3. Скопируйте содержимое Assets пакета в Assets проекта с заменой одноименных файлов. Дождитесь импорта FBX и компиляции.
4. Выберите **Train Summer → Create Prototype Scene** для короткого теста или **Train Summer → Create Long Route Scene** для длинного маршрута.
5. Нажмите Play.

При обновлении с 0.1/0.2 сцену нужно пересоздать: добавилась ссылка поезда на RoutePath. Генератор предложит сохранить открытую сцену и перезапишет Generated/Prototype.unity либо Generated/Prototype_Long.unity. Ручные изменения сохраните в другой сцене. URP Asset проекта не изменяется.

Папки Runtime/Editor теперь имеют asmdef. Для приложенных тестов нужен Unity Test Framework; установите его через Package Manager, если отсутствует. При собственной структуре сборок добавьте ссылку TrainSummer.Runtime в свои asmdef.

## Новое в 0.4: вылазки и ремонт
- **Две новые модели:** SupplyCrate (ящик припасов, 3648 / 360 / 108 треугольников) и RepairBench (верстак, 4212 / 380 / 84 треугольника). Оба ассета имеют три LOD, исходник Blender, FBX, генератор и студийный рендер.
- В каждом станционном доме слева от входа стоит ящик. Навести камеру и нажать E: один раз за сессию он выдаст 4 металлические детали и 2 единицы ткани. Ящик остается на месте; крышка пока не анимирована.
- **Tab** показывает временный список ресурсов. Мир и управление движением продолжают работать; взаимодействие E при открытом списке отключено. Это промежуточный интерфейс, физического 3D-рюкзака пока нет.
- Верстак установлен сзади слева в вагоне, напротив выходного проема. Остановите поезд, наведитесь на верстак, нажмите E: **3 детали + 1 ткань → до +25 процентных пунктов состояния**. Если состояние уже 100%, поезд движется или ресурсов не хватает, списания нет.
- Начальное состояние поезда — 60%; износ — 0,006 процентного пункта на метр. При 0% поезд тормозит и не может продолжить движение до ремонта. Топливо расходуется отдельно. Можно вручную остановиться у пульта, отремонтироваться и снова снять тормоз.
- HUD уменьшен; **F3** открывает справку по управлению. Состояние поезда видно в верхнем углу, количество ресурсов — в списке Tab.
- Общий IInteractable теперь обслуживает канистры, ящики и верстак. ResourceInventory хранит ресурсы отдельно от их UI. Сохранения пока нет: новая сессия сбрасывает ресурсы и лут.

В Unity-тесты добавлены сценарии повторного лута, переполнения, успешного ремонта, отсутствующей ткани, ремонта при движении, полного состояния, отрицательных транзакций и восстановления сломанного поезда. **Они не запускались в Unity.**

Генераторы новых моделей используют общий `prop_pipeline.py` рядом со скриптами — сохраняйте папку Blender целиком.

    blender -b --python Tools/Blender/generate_supply_crate.py -- --project /UnityProject --render
    blender -b --python Tools/Blender/generate_repair_bench.py -- --project /UnityProject --render
    blender -b --python Tools/Blender/validate_survival_props.py -- --project /UnityProject

Все генераторы очищают открытую сцену Blender. Выходные FBX — Assets/Models, .blend — Tools/Blender/Source, PNG — Previews.

## Что изменилось в 0.3
- **RoutePath:** плавная горизонтальная кривая и таблица длины дуги. Скорость поезда задается в метрах вдоль пути. Рельсы и шпалы следуют той же кривой.
- **Несколько остановок:** после возвращения к пульту можно последовательно отправляться на следующие станции; на конце тестового маршрута поезд останавливается окончательно.
- **Пул участков:** при старте создаются семь участков; при смене окна они перенастраиваются и переиспользуются. Объекты участка не создаются и не уничтожаются во время переходов между чанками. Сам прогрев синхронный, а перенастройка коллайдеров все еще может давать пики CPU.
- **StationHouse:** отдельная модель станционного домика с крыльцом, окнами, дверным проемом, столом, полкой, крышей и тремя LOD: 5616 / 540 / 384 треугольника.
- На каждой из четырех станций домик стоит за платформой. Топливо лежит на столе внутри. Ступени соединяют платформу с землей.
- **ModelSetup:** общий Editor-адаптер наших FBX: ориентация по маркерам, URP-материалы и LODGroup. Столкновения по-прежнему заданы простыми BoxCollider отдельно от визуальных мешей.
- Повторный программный вызов Collect не выдает топливо второй раз. Пульт работает только при нахождении игрока на поезде.
- Контроллер синхронизирует измененные трансформы физики перед движением; возвращение после падения учитывает поворот поезда.

Сохранены вагон из 0.2 с интерьером и LOD, перенос скорости при прыжке, летний солнечный цикл, RU/EN и FPS-переключатель.

## Управление и вылазка
WASD — движение; мышь — обзор; Space — прыжок; Esc — освободить/захватить курсор; E — собрать топливо либо переключить тормоз/отправиться у переднего пульта. F1 — RU/EN; F2 — FPS; F3 — справка; Tab — список ресурсов. Esc не ставит мир на паузу.

1. Поезд трогается сам и автоматически останавливается у станции.
2. Выйдите через задний проем справа, спуститесь по ступеням на платформу.
3. Дом стоит за противоположным краем платформы. Спуститесь по небольшим ступеням, войдите через крыльцо.
4. Подойдите к оранжевой канистре на столе, наведитесь, нажмите E. Затем обыщите ящик слева от входа.
5. Вернитесь в вагон, используйте верстак сзади слева. После ремонта нажмите E возле переднего пульта.

При ручном торможении в пути повторное E у пульта снимает тормоз. Отправление со станции ручное; таймера отправления пока нет.

## Два маршрута
**Короткий:** остановки на 160 / 640 / 1200 / 1800 м; конец пути около 2214 м. Первый перегон около 25 секунд, следующие — примерно 65–80 секунд. Начальный запас топлива 30, канистра дает 20.

**Длинный:** остановки на 2800 / 6000 / 9200 / 12400 м; путь около 15,7 км. Первый перегон около 5 мин 55 с, следующие — около 6 мин 45 с при 8 м/с. Начальное топливо 75, канистра дает 80. Это численный расчет без учета ручного торможения; длительность стоянки определяется игроком.

## Blender-модели
Исходники .blend находятся в Tools/Blender/Source вне Assets, поэтому для импорта FBX Blender на компьютере с Unity не требуется.

    blender -b --python Tools/Blender/generate_station_house.py -- --project /UnityProject --render
    blender -b --python Tools/Blender/validate_station_house.py -- --project /UnityProject

Для вагона аналогично: generate_train_car.py и validate_train_car.py. Для канистры: generate_fuel_can.py. Генераторы очищают сцену Blender: запускайте в background или отдельном файле. FBX экспортируются в Assets/Models. Параметр --render у генераторов дома и вагона создает изображения в Previews.

Исходный вагон целый: изображение разреза интерьера сделано после сохранения FBX/BLEND. На импортированном общем FBX присутствуют все LOD; используйте LODGroup. Генератор Unity-сцены настраивает его автоматически.

## Проверить в Unity
- Console без ошибок; Test Runner → EditMode → Run All.
- Сцена генерируется, вагон и домики правильно ориентированы, материалы отображаются.
- Игрок не отстает от поворачивающего вагона; прыжок сохраняет начальную скорость, приземление на землю ее сбрасывает.
- Двери, крыльцо и ступени проходимы; канистра собирается один раз.
- Обыскать ящик дважды: ресурсы выдаются один раз.
- На остановке выполнить ремонт: снять 3 детали и 1 ткань, восстановить до 25 пунктов. При движении и нехватке ткани убедиться, что ресурсы не тратятся.
- Tab открывает список, F3 — справку; во время открытого списка E ничего не активирует.
- Пройти все четыре остановки, проверить конечную остановку и расход состояния по пути.
- В Route Streamer остается ровно семь дочерних Route_* после нескольких перегонов; проверить GC/CPU-пики при перенастройке и прогреве пула.
- Профилировать standalone Development Build: кадры, коллайдеры, LOD, draw calls. Заявления об FPS пока делать нельзя.

## Ограничения следующего этапа
Материалы базовые: нет PBR-текстур, старения, финальной UV-подготовки и фотореализма. Деревья — примитивы без LOD; колеса не анимированы, окна без стекол.
Маршрут конечный и плоский; смещения начала координат нет. Четыре станции остаются в сцене постоянно; нет additive загрузки станций и сохранений. Пул работает с примитивами и может быть дорог по числу Renderer/Collider; это основа для дальнейшей оптимизации.
Пока нет оружия, врагов, физического 3D-инвентаря, общего крафта, потребностей игрока, таймера отправления и полноценного меню. Есть только два ресурса и один рецепт ремонта; инструменты верстака — статические части модели, их нельзя брать отдельно. RU/EN — временные строки, не Unity Localization. Ночь упрощена, без полноценного звездного неба и лунного света.
